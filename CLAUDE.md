# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal website for Mohammad Mahdi Molaei (triplem.dev), built on Nuxt 4. Bilingual (English default, Persian/RTL under `/fa`): a homepage made of section components (3D hero, experience timeline), an About page, a Contact page with a server-side form, a Support page, and a Markdown blog.

## Commands

Package manager is **pnpm** (see `packageManager` in `package.json`); Node `^22.21.1`.

```bash
pnpm install        # also runs `nuxt prepare` (generates .nuxt/ types and eslint config)
pnpm dev            # dev server on http://localhost:3000
pnpm build          # production build
pnpm generate       # static generation
pnpm preview        # preview production build
pnpm lint           # eslint (cached)
pnpm lint:fix       # eslint --fix
pnpm format         # prettier --write .
pnpm format:check   # prettier --check .
pnpm typecheck      # nuxt typecheck (vue-tsc)
pnpm check          # lint + format:check + typecheck + covers:check
pnpm covers         # rebuild every blog cover's light twin and Open Graph PNG
pnpm covers:check   # validate covers; every post must point at one
```

pnpm comes from corepack, which must be new enough to map pnpm ≥ 11 to `bin/pnpm.mjs` (0.36, bundled with Node 24, is). If `pnpm` or `corepack pnpm` fails with `Cannot find module …\corepack\v1\pnpm\<version>\bin\pnpm.cjs`, an older corepack cached that version with the pre-11 entry point. Delete `%LOCALAPPDATA%\node\corepack\v1\pnpm\<version>` (`~/.cache/node/corepack/v1/pnpm/<version>` on Linux/macOS) and corepack re-fetches it correctly. Keep `pnpm-workspace.yaml`: it holds `shamefullyHoist`, the `allowBuilds` approvals (without them pnpm prompts for esbuild/sharp builds) and the extra `supportedArchitectures` for Docker.

There is no test runner configured. `tsconfig.json` and `eslint.config.mjs` depend on files generated into `.nuxt/`, so run `pnpm install` or `nuxt prepare` first in a fresh checkout. ESLint ignores `.agents/` and `.claude/` (vendored skills).

**Don't run `pnpm build` on Windows**: Nitro's `node-externals` Rollup plugin (nitropack 2.13.x) compares a `pathe`-normalised id with a backslash path from `fileURLToPath`, so every dependency reached through an absolute id (reka-ui, zod, motion-v, …) is inlined into the server bundle instead of externalised, and Rollup crawls thousands of modules through a slow resolver. The build looks hung at "Building Nuxt Nitro server" and takes tens of minutes. Build in Linux instead: `docker build -t triplem.dev .` uses the `Dockerfile` (multi-stage; `pnpm fetch` layer cached on the lockfile, runtime ships only `.output` on Node Alpine, SQLite cache in `/app/.data`, secrets via `--env-file .env` at run time). The same build finishes in about a minute there.

Code style: 4-space indent, double quotes, semicolons, 100 columns. Prettier (`.prettierrc.json`) owns formatting; ESLint checks code quality, and `eslint-config-prettier` (last entry in `eslint.config.mjs`) turns off its formatting rules so the two never conflict. `content/` is excluded from Prettier.

## Architecture

- **Nuxt 4 layout**: source lives under `app/` (`~`/`@` resolves to `app/`). `app/app.vue` wraps everything in motion-v `<MotionConfig reduced-motion="user">`, sets the `html.dark` class, i18n SEO head, and the title template. `app/layouts/default.vue` renders the nav, footer, and the fixed `tech-grid`/`grain` backdrops.
- **Site metadata**: `app/app.meta.ts` is the single source for site/author info, social links, and URLs. Use it for SEO/meta values instead of hardcoding.
- **i18n**: `@nuxtjs/i18n` with `en` (default, no prefix) and `fa` (`/fa`, `dir: rtl`), strategy `prefix_except_default`, browser detection off. All user-visible copy lives in `i18n/locales/{en,fa}.json`, keyed by homepage section (`hero`, `about`, `experience`, `blog`, ...). Every copy change has to land in both files. Use logical properties (`start`/`end`, `ms`/`me`) so layouts flip correctly in RTL. LTR islands inside Persian text (emails, URLs, handles) get `dir="ltr"` plus the `latin` (or `latin-display`) utility from `main.css`; otherwise IRANSans FaNum renders their digits as Persian. vue-i18n treats `@` and `|` as syntax: write a literal `@` as `{'@'}`.
- **Experience timeline**: `app/data/experience.ts` (and `app/data/stack.ts` for the Stack graph) holds only the untranslatable structure (id, host, link, stack, screenshots in `public/images/work/`). Prose lives in i18n under `experience.items.<id>`: `highlights.N` is indexed by the entry's `highlights` count and `alt.N` by its `shots`. Adding an entry means updating the data file and both locale files together.
- **Blog (Nuxt Content v3)**: `content.config.ts` defines one collection per locale (`blog_en`, `blog_fa`) whose path prefixes mirror the i18n routes (`content/en/blog/x.md` → `/blog/x`, `content/fa/blog/x.md` → `/fa/blog/x`). That lets pages query by `route.path` directly. Frontmatter: `title`, `description`, `date`, `cover`, `tags`, `draft`. `minutes` (reading time) is computed by the `content:file:afterParse` hook in `nuxt.config.ts`. Drafts show only in `nuxt dev` (`showDrafts` in `app/composables/useBlog.ts`); every query has to respect it. `useBlog.ts` also provides locale-aware date/number formatting (Persian calendar and digits on `/fa`). Code blocks use the `vitesse-dark` Shiki theme and render through `app/components/content/ProsePre.vue`, which stays dark in both themes. Content uses SQLite (`better-sqlite3`, local DB in `.data/`).
- **Blog covers**: every post has hand-drawn SVG line art at `public/images/blog/<slug>.svg`, 1200×630 with a transparent background and only the six dark-palette colours listed in `.github/blog-cover.md` (the spec: canvas, safe area, palette, motifs, allowed elements, review loop). `scripts/blog-cover.mjs` validates a cover (no text, scripts, styles, external refs or off-palette colours), derives `<slug>-light.svg` by swapping each colour for its light twin, and renders `<slug>.png` (dark art on the surface colour, with crop marks and the /// mark) for Open Graph with sharp. `ensure <slug>` does all of that and sets `cover:` in both locales' posts; if the SVG is missing or invalid it writes a deterministic generated cover instead. `BlogCover` shows the dark or light file from `useTheme()` (the cookie means SSR already picks the right one) inside a `bg-surface` frame with crop marks, because covers use the surface colour for knock-outs. It appears in `BlogRow`, `BlogFeatured` and `BlogPostHeader`. `blogCover()` in `useBlog.ts` maps a cover to its derived files, and `[slug].vue` uses the PNG for `og:image`, `twitter:card` and the JSON-LD `image`. The daily-article workflow (`.github/workflows/daily-article.yml`) has Claude draw the cover, check it and review the PNG, then a "Finalize cover" step runs `ensure` as a safety net and the PR embeds the PNG.
- **Pages**: `/` (sections in `components/home/`), `/about` (`components/about/`: portrait, facts, method, toolbox, path, now; `AboutFacts` and `AboutMethod` are shared with `HomeAbout`), `/contact` (`components/contact/`: `ContactChannels`, `ContactForm`; `?topic=<id>` preselects a topic), `/team` (`components/team/`), `/support` (`components/support/`), `/blog`, `/blog/[slug]`. Page copy lives in i18n under `aboutPage.*`, `contactPage.*`, `teamPage.*` and `supportPage.*`. `app.meta.ts` has an optional `cv` path; `/about` shows a download button only when it's set.
- **Team page**: `app/data/team.ts` holds the people: `CORE_TEAM` is Triple M, one person per slash of the mark, left to right (index N is slash N in the 3D scene, gold middle slash = the site owner), and `COLLABORATORS` the wider circle. Names, roles and optional `surname`/`bio` are in i18n under `teamPage.people.<id>` / `teamPage.roles.<role>` (optional keys render only when present, checked with `te()`); photos, `links` and an internal `page` live in the data file. `TeamHero` reuses `HeroStage`: hovering or tapping a slash shows that person in the readout, and hovering or focusing a core card lights its slash (the page keeps one shared slash index). The core card row is forced `dir="ltr"` (each card's content keeps the page direction) so card N stays under slash N in Persian too, like the logo. Portraits render in grayscale; collaborators without a photo get a shadcn `Avatar` with their initial.
- **Support page**: `app/data/support.ts` holds the Reymit link and the USDT wallets (network, chain, `tm:` icon, address); the copy is in i18n under `supportPage.*`. Before adding or changing an address, verify its checksum (EIP-55 for BEP20, base58check for TRC20), because a typo loses the money. `SupportWallet` shows a QR code, the address with its first and last six characters in gold (people compare those after pasting, which defends against address poisoning), a copy button and a network warning. `SupportQr` draws the QR as one SVG path with `uqr`'s `encode()` and keeps it dark-on-light in both themes, because many scanners can't read inverted codes. The page is linked from the header nav (`useNavLinks`) and the footer.
- **Contact API**: `shared/contact.ts` (imported as `#shared/contact`) is the one contract for the form and the server: zod schema, topics, limits and the minimum fill time. `server/api/contact.post.ts` checks, in order: a per-IP (5 per 15 min) and a global (60 per hour) in-memory rate limit (`server/utils/rate-limit.ts`), then the honeypot (`website`) and fill time (`elapsed`), which answer `{ ok: true }` without sending so bots learn nothing, then the schema (422 with `data.fields`). `server/utils/mailer.ts` sends through nodemailer + Gmail SMTP to the owner only, with the visitor as Reply-To; there is deliberately no auto-reply to the visitor (it would make the form a spam relay). It connects to the SMTP host over IPv4 when one resolves, because nodemailer otherwise picks a random A/AAAA record and hosts without an IPv6 route fail with ENETUNREACH. Config is server-only `runtimeConfig.smtp`/`contact`, set with `NUXT_SMTP_*` and `NUXT_CONTACT_TO` (see `.env.example`; use a Google App Password). Without SMTP credentials, `nuxt dev` logs the message instead of sending and production returns 503. Behind Nginx, set `proxy_set_header X-Real-IP $remote_addr;` so the rate limit sees real client IPs. The limiter is per process: move it to shared storage if the app ever runs as several instances.
- **Theme**: `useTheme()` (`app/composables/useTheme.ts`) stores the theme in the `tm-theme` cookie so SSR renders the correct `html.dark` class with no flash. Dark is the default. The toggle, `<html>`, and the 3D scene all read the shared `useState`.
- **Styling**: Tailwind CSS v4 via `@tailwindcss/vite` (no `tailwind.config`). All tokens live in `app/assets/css/main.css`: `:root` is the light ("editorial ivory") palette, `.dark` overrides it, and `@custom-variant dark` targets a `.dark` ancestor. For page design, use the brand color roles (`surface`, `elevated`, `subtle`, `faint`, `hairline`, `gold`, `on-gold`, `glass`, ...) rather than the shadcn roles. Fonts are self-hosted `@font-face` declarations in `main.css` (files in `public/fonts/`, `@nuxt/fonts` uses the `local` provider). Latin: Familjen Grotesk (headline), Instrument Sans (body), IBM Plex Mono (code/labels). `[dir="rtl"]` swaps to Kalameh/IRANSans and drops letter-spacing. Above-the-fold fonts are preloaded in `nuxt.config.ts`.
- **3D hero**: TresJS (`@tresjs/nuxt`, three.js). `HeroStage.client.vue` (client-only) owns the canvas, pointer input, off-screen pausing, and a WebGL-unavailable fallback. `HeroSlashScene.vue` loads `public/models/triplem-slash.glb` and does all per-frame work in the render loop. The two communicate through a plain mutable object from `app/lib/slash-input.ts`, which is kept non-reactive on purpose so the hot path never triggers Vue updates. The scene is `aria-hidden`; `HomeHero` carries the accessible content.
- **Animation**: `motion-v`. `SiteReveal` is the standard once-only scroll reveal. Reduced motion is honoured globally via `MotionConfig` and in the hero via `usePreferredReducedMotion`.
- **Components**: auto-imported with path prefixes (`components/home/HomeHero.vue` → `<HomeHero>`, `components/site/*` → `<Site*>`). Pages and `Home*` sections are composition surfaces; feature pieces live in `components/{hero,stack,experience,blog}/`. Shared building blocks are in `components/site/`: `SiteSection` (anchor + header + `titleId` slot prop), `SiteMark` (logo, `accent`/`tone` props), `SiteArrow` (RTL-aware arrow), `SiteCopyButton`, and `SiteOutlineTitle`. Social links come from `socialLinks` in `app.meta.ts`. External links use `<NuxtLink target="_blank">`, which adds `rel` automatically.
- **shadcn-vue**: components are in `app/components/ui/` (`Ui` prefix: `<UiButton>`, `<UiBadge>`, `<UiToggle>`, `<UiToggleGroup>`, `<UiInputGroup>`, `<UiSeparator>`, `<UiField*>`, `<UiAlert>`, `<UiSpinner>`, `<UiAvatar>`). `components.json` has `"rtl": true`, so generated classes are logical. Their `cva` variants are edited to match the brand: Button `ink`/`gold`/`outline`/`ghost`/`quiet`/`link` with sizes `label` (eyebrow type)/`inline`/`icon`, Toggle `outline`/`node`/`chip`, and Badge `outline`/`mono`/`gold`. Prefer a variant over restyling with `class`. Two local deviations from upstream: `Spinner` uses the `tm:loader` icon instead of `@lucide/vue`, and `FieldError` renders nothing when every entry in `errors` is empty (upstream renders an empty `role="alert"` list). Forms follow the shadcn-vue rules: `FieldGroup` + `Field`, `data-invalid` on the `Field` and `aria-invalid` on the control. Use `cn()` from `app/lib/utils.ts` for class merging. ESLint turns off `vue/require-default-prop` for `ui/` so generated files stay close to upstream. The shadcn CLI (like `nuxt upgrade`) installs dependencies through `corepack pnpm`; see the corepack note under Commands if that fails.
- **Icons**: `@nuxt/icon` with a local custom collection. Every icon is an SVG in `app/assets/icons/`, used as `<Icon name="tm:<file>" />`. Icons are bundled into the client (`provider: "none"`), and `app/app.config.ts` sets `cssLayer: "base"` so Tailwind can size them. Monochrome icons render in CSS mask mode, so set `fill`/`stroke="currentColor"` on each element. The multi-colour logo (`mark.svg`) reads `--mark-*` CSS variables and must use `mode="svg"` (`SiteMark` does this). Decorative illustrations that need root SVG attributes or data-driven geometry stay as components (`components/art/`, `StackGraph`).
- **SSR width**: `app/plugins/ssr-width.ts` calls `provideSSRWidth(1024)` so VueUse breakpoint/media-query composables render consistently on the server.
- **Other modules**: `@nuxt/image`, `@nuxt/hints`, `@vueuse/nuxt`, `@nuxt/eslint`.

## Agent skills

Project-local skills are installed under `.claude/skills/` and `.agents/skills/` (tracked in `skills-lock.json`), covering Nuxt, Nuxt Content, i18n, Vue, reka-ui, shadcn-vue, motion/animation design, etc. Prefer invoking the relevant skill when working in those areas.
